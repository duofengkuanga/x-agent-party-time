# 本地规格文档

本项目以 `docs/specs/` 中的 Markdown 文档保存需求、实施决策与验收标准，不再依赖 GitHub Issues。

- 调用 `to-spec` 时，只汇总当前已讨论的内容，按该 skill 的模板生成本地 spec；文件名遵守项目的小驼峰规则。
- 已整理到可交给实施 Agent 的 spec 使用 frontmatter `status: ready-for-agent`。这表示需求可以进入实施任务，不表示功能已经实现或验证通过。
- 领域词汇以根 `CONTEXT.md` 为准，已确认取舍以 `docs/adr/` 为依据；设计文档提供技术依据，spec 汇总本次需求与验收范围。
- Skill 中“发布到 issue tracker”在本项目解释为保存仓库文档并交付文件链接；不要求 GitHub 账号、Issue 编号、标签或关联关系。
- 需要进一步拆分任务时，使用仓库文档记录顺序和依赖；`to-spec` 本身不自动拆分任务。
- 用户另行明确要求操作 GitHub 时，按该次授权处理；旧 Issue 仅是历史资料，不自动迁移、修改或删除。

交付前确认模板章节、用户故事和验收范围完整，本地引用可达，并完成项目要求的命名与差异检查。结构和链接可由工具检查；是否忠实覆盖用户决策需结合会话、领域文档和 ADR 复核。
