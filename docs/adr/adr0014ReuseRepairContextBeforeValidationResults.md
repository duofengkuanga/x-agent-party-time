# 先复用修复上下文，再设计验证结果复用

本记录汇总已确认的设计决策；实现与运行验证由关联工单跟踪，功能验证与性能收益分别判断。

Repair 到 Update 的优化首先补齐跨会话上下文，并依据实际检查覆盖关系合并同轮重复命令；历史验证通过结果的自动复用作为后续独立能力。已有验证摘要用于理解先前工作，第一版仍满足当前工程对本阶段的验收要求，避免把上下文交接误当成免检凭据。

沿用 [ADR-0001](adr0001KeepRunnerDomainNeutral.md) 的执行边界：Cooking 负责业务交接，Codex 按 Skill 执行，xapt 提供通用运行能力。稳定流程继续由 `x-skills` 提供，结构化输入输出由本工程定义；本次优化不修改目标工程的 `AGENTS.md`。

以修复到交付的总成本衡量优化效果：Repair 满足修复验收，Update 对选中的最终组合补齐交付验收，不为缩短 Update 的显示耗时而要求每次 Repair 提前执行全部发布检查。保留两阶段职责，接受第一版仍可能重跑跨阶段检查，以控制证据有效性判断的复杂度。

## 交接归属与内容

Repair Handoff 关联产生候选提交的来源 Repair Attempt 和提交，随 Update Batch 一起冻结。同一 Bug 的候选可能累积自多次成功修复，应保留各次交接与其提交的关系；后续会话的新结论不替换既有批次的交接，单次修复的验证结论也不扩展为整个组合的验证结论。

交接采用精简的结构化摘要，复用已有修改、验证和警告信息，补充已用验证入口与必要参数、已验证的环境解决办法、影响范围与关键入口、未验证或未完成事项，以及结论适用条件和限制。不默认加载完整聊天或日志；命令是需要结合当前仓库核实的历史线索，本机绝对路径与敏感环境值不进入 Server 交接数据。

## 数据契约与原子冻结

| 数据                                      | 归属与约束                                                                                                     |
| ----------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| 修改、验证结果、警告                      | 复用现有 Execution Outcome 字段与摘要限制。                                                                    |
| 验证命令与运行条件                        | 位于专门的 `handoff` 字段，关联同一 Outcome 已有的验证条目，不重复保存通过状态。                               |
| 环境经验、影响入口、剩余事项、适用限制    | 位于 `handoff`，结构化列表与文本由 Server Schema 限定上限；确实没有内容时允许为空。                            |
| 来源 Repair Attempt、Execution 与候选提交 | Cooking 建立关联，模型不填写平台 ID。来源标识留在平台记录，Update Brief 只携带理解交接所需的提交关系与上下文。 |
| 批次交接快照                              | 与批次成员、顺序、Execution 入队在同一事务中保存，冻结后保持不变。                                             |

产生提交的成功 Repair 必须返回 `handoff`；失败或确认无需修改时不创建候选交接。候选使用完整 Commit Hash，并沿用 xapt 的通用 Git 结果断言核验；Server 不以短 Hash 猜测来源。缺失交接、来源覆盖不完整或数据矛盾使冻结失败，不留下部分批次，也不启动后续 Push。

此处是对 [ADR-0011](adr0011MinimizeCodexExecutionBriefsAndOutcomes.md) 的有界补充：交接保存当前 Update 无法从本机推导的历史事实，仍由 Server 唯一拥有 Schema，Skill 定义语义与流程，不复制字段定义。

格式 Schema 使用 Codex 支持的约束；不受其支持的上下文字符串检查由 Server 配置为通用结果断言，xapt 在正常完成和只读同步的结果上传前执行。Server 同时校验相同约束，Runner 不需要理解 Repair Handoff 的业务含义。

## 更新执行顺序

Update 先核实交接、当前仓库规则、必要工具和 Git 状态，再集成全部冻结候选，对最终组合制定并执行一次验收计划；根据实际覆盖关系合并能共同完成的命令。冲突在集成时处理，验收后的代码或输入变化触发受影响部分的重验；远端状态与推送结果始终现场核验。这样减少逐个候选重复完整构建，同时保留对最终交付状态的验证责任。

## 不完整与失效信息

新流程中，每次产生候选提交的成功 Repair 都必须提供 Repair Handoff；确实没有的信息允许明确为空，不为填充交接而增加无关探索。摘要不足以指导某项操作时，Update 只补查该项；整个交接缺失、来源不匹配或冻结数据矛盾属于契约错误，应暂停并报告具体原因，不静默回退为从头探索。

历史线索过期或互相冲突时，以当前仓库配置和实际执行结果为准，局部重新查证，其余有效线索继续使用。Update 在本次执行记录中说明采用的结论与改变原因，原冻结交接保持不变。第一版不增加跨 Bug 的工程经验库，避免同时引入经验覆盖与过期规则。

恢复时沿用现有 Skill 的阶段核验规则，从首个未完成阶段继续；Push 等操作的结果未知时先查询实际状态，不把未收到结果当成需要重新执行的依据。

## 可观察性与角色边界

在现有执行详情中，向工程负责人解释沿用的入口与环境经验、失效线索及重新查证的原因，以及最终检查与命令合并依据。第一版不增加独立分析页面或复杂指标系统。

测试负责人继续看到业务结果与验证摘要。命令、环境诊断与来源引用使用专门的技术字段，并在 Server 读取投影中按角色过滤；不能仅在界面隐藏，也不能把这些内容混入所有角色都能读取的摘要。

## 契约切换

新流程统一使用新契约，不为新任务放宽结果校验。用户已明确允许将现有数据重写为最新结构，同时要求保留每条数据及其原有业务内容：Schema 27/28 通过显式离线迁移升级到 29，先验证备份，再以事务升级结构、转换历史结果并逐字段核对原有记录。应用运行时只处理最新格式，不增加历史兼容读取分支。迁移入口与恢复方式见 [README](../../README.md#保留数据升级-server)。

切换前清点未完成旧任务；旧执行、待交付候选和未完成修复或更新流程必须先在旧 Server 完成，否则迁移中止并保留原库。旧修复结果的交接限制如实注明历史未记录的信息，不补造命令、验证或环境经验；批次交接根据已有来源 Attempt、Execution 和完整提交关联重建。转换后的结果通过当前契约校验，旧字段内容保持不变。Server、xapt 和 Skill Bundle 按核验过的组合启用。旧 Task 固定 Bundle，不能靠更新 Skill 文件改写其历史执行事实。

## 验收依据

以下是验收要求；自动化检查和真实会话证据分别记录，完成一次功能验证不代表已经证明性能收益。

| 场景               | 完成证据                                                                               |
| ------------------ | -------------------------------------------------------------------------------------- |
| 单候选更新         | 真实 Agent 会话使用已核实的运行入口，没有重复寻找工具或重踩已解决的环境问题。          |
| 多候选、多次修复   | 自动化测试证明来源关联完整、冻结不可变；真实会话针对最终组合验收，没有逐候选完整构建。 |
| 线索失效或冲突     | 真实会话只重新查证受影响部分，同时完成当前工程要求的全部适用检查。                     |
| 交接缺失或来源错误 | 自动化测试证明契约错误可见，事务不留下部分批次，不入队执行或继续 Push。                |
| 中断恢复           | 恢复场景证明已完成阶段得到核验，结果未知的副作用先查询实际状态。                       |
| 角色与契约切换     | 响应级测试证明测试负责人收不到技术字段；契约测试证明旧格式不会被静默接受。             |

数据关联、Schema、原子冻结和角色投影使用自动化测试验证；减少重复探索、判断命令覆盖关系等语义行为，使用实际加载新版 Skill 的 Agent 会话验证。现有 `x-skills` 文案检查和预写 Git 沙盒操作不能替代后者。

对照选择不同构建体系，保持任务输入与验收要求可比，记录修复到交付的总耗时和重复命令，将人工等待单独列出。以完整流程成本和重复行为的实际变化判断收益，不预先承诺固定提速比例。验证日志须保留执行范围、结果、失败及未完成项；实施时为新增检查提供实际可运行入口。
