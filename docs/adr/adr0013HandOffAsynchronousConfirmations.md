# 将异步确认交给原 Codex 会话处理

Repair 与 Update 收到带 `delivery: async` 和非空 `questions` 的 Codex 消息后，xapt 保存脱敏问题和待上报的交接回执，停止当前 Turn，并关闭这一执行专属的 App Server。只有确认进程退出后，平台才记录 `HANDED_OFF`，网页显示“等待人工确认”、原会话入口和“同步状态”。准备期间保留等待交互记录；它不能被网页回答或自动重试。普通文字不触发交接，原有同步审批继续使用 Interaction。这个选择让负责人使用 Codex 的完整上下文处理问题，代价是人工切换应用并主动同步一次。

交接后的 Execution 已结束托管，但 Repair 或 Update 仍未完成。原交接记录不可改写；同步只读取最新完整 Turn，校验原结果约束和证据后追加 External Session Attempt。无有效结果时继续等待，不扫描旧结果。平台保留待人工处理工作区的调度保护，允许原会话只读同步和独立工作区任务。同步接受有效终态结果后解除该保护。

重启重放交接回执前，xapt 使用不启动 Turn 的临时会话加载与关闭确认写入占用已释放；遇到现有持有者时保留回执等待。交接准备记录过期不会回到自动执行队列，也不会依赖删除锁文件解锁。该过程不代表用户已经批准权限变更。
