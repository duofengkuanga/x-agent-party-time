# Cooking Bug 生命周期与结构化进展实施规格

状态：已确认，待按 CBL-001 至 CBL-007 实施和验收

来源：2026-07-29 产品 grilling 对谈。

## 规则优先级

本规格是当前 Bug 看板、执行队列、取消、反馈、Interaction、Cleanup 和 Update Batch 的唯一实施约束，已取代并清理早于 2026-07-29 的相关临时规格。项目仍处于开发期：直接替换旧 Schema、Contract、状态和交互，不增加迁移、兼容字段、Fallback、旧数据映射或双写。

## 产品目标

缺陷进入自动生命周期后，除 Codex 主动请求信息、请求权限或 Execution 已结束且需要重新执行外，用户无需介入。缺陷详情是结构化生命周期观察面和少数 Interaction 处理面，不是 Codex 聊天客户端。

核心结果：

- 看板保持六个业务阶段：待修复、修复中、待更新、更新中、待验证、已完成。
- 运行过程按生命周期语义组织为旧到新的时间线，打开详情时定位最新节点。
- Codex 成功与失败均返回强制结构化结果；平台不调用第二个 AI 总结或改写。
- 权限和用户输入使用 Codex 原生 Interaction 语义。
- 同工程实际执行串行，但等待 Interaction 的任务挂起并释放工程通道。
- Repair 使用 `apt/repair/<bug-id>` 唯一临时分支，Update Batch 使用 Detached HEAD；临时 Worktree 不得占用工程目标分支。
- 删除提测单级全局修复队列和人工排序，改为工程级自动 FIFO。
- Update Batch 在更新中列显示为唯一共享批次卡，而不是重复的 Bug 卡。
- 普通反馈入口被删除；反馈只属于验证失败或重新打开等明确生命周期动作。
- 待修复 Bug 可取消和恢复；已完成 Bug 可归档和移出归档。
- 所有生命周期拖拽和对应按钮只允许提测单测试负责人操作。

## 明确推翻的旧语义

- 不再提供常驻反馈、继续修复文本框、继续统一更新文本框、Steer、Queue 或 Pause。
- 不再允许修复中或待更新 Bug 取消。
- 不再为 Bug 取消创建 Cleanup；Cleanup 只服务于提测单关闭。
- 已取消 Bug 可以恢复到待修复，不再是不可恢复终态。
- 新增归档概念，但归档不是 Bug Stage；它只是 `DONE` Bug 的可见性属性。
- 不再使用垃圾桶隐喻承载不可恢复终态；入口语义为“已取消”。
- 不再手动管理全局修复队列、Position 或上下移动。
- Interaction 等待不再继续占用同工程执行通道。
- 权限请求不再只有“拒绝 / 本次会话允许”，增加“仅允许这一次”。
- 不再只依赖长篇 `summary`；成功和失败结果都必须提供结构化字段。
- 不展示实时 Codex 命令流、工具流或逐字输出。
- 不新增失败列；失败对象留在原业务阶段。
- 不提供部署回退按钮；已完成后的回退诉求通过重新打开反馈交给 Codex 处理。
- 不保留历史反馈记录兼容展示，允许清空开发数据库按最新 Schema 重建。

## 非目标

- 不把 Web 改造成 Codex App 的聊天界面。
- 不实现实时 `turn/steer`、客户端消息排队或任务暂停。
- 不在业务层复制 Codex 的网络、Token、上下文或工具自动恢复策略。
- 不由平台判断 Codex 是否应该重试、跳过验证、回退或更换方案。
- 不展示完整 App Server 事件流、stdout/stderr 或原始 JSON 作为默认内容。
- 不允许手动跨越自动阶段。
- 不允许工程负责人代替测试负责人操作 Bug 生命周期。
- 不迁移或兼容旧开发数据。
- 不允许 Repair 或 Update Worktree 直接 checkout `main`、`testForAPT` 等工程目标分支。

## 共同完成定义

每张 Ticket 完成前必须：

- 先对待修改符号执行 GitNexus upstream impact，并处理 HIGH/CRITICAL 风险。
- 交付一个可以独立演示的纵向用户结果，不只修改单层 Contract 或样式。
- 使用 Server Projection 输出唯一权限、Action 和视觉状态；前端不复制领域判断。
- 同步删除该 Ticket 已取代的旧 Action、字段、表、分支、测试和文案，不保留兼容入口。
- 检查界面中文文案、按钮状态、滚动可达性、纸张/夜间主题和桌面视口。
- 运行相关测试、类型检查及必要浏览器验证。
- 提交前运行 GitNexus `detect_changes`，确认影响范围符合 Ticket。
- 从 Standards 与 Spec 两个轴完成代码评审。
