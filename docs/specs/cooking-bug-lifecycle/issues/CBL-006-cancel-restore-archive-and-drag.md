# CBL-006 — 取消恢复、完成归档与测试负责人拖拽矩阵

**What to build:** 将取消限制为待修复 Bug，并允许从“已取消”恢复；为已完成 Bug 增加独立归档属性和归档抽屉。看板只允许四种明确拖拽，拖拽和卡片按钮走同一 Action，且全部生命周期操作只允许提测单测试负责人执行。

**Blocked by:** CBL-003 — 非阻塞工程串行调度与全局队列删除；CBL-005 — 上下文化验证反馈、重新打开与通用反馈删除。

**Status:** ready-for-agent

## 取消与恢复

- 唯一允许的取消转换：`WAITING_FOR_REPAIR -> CANCELLED`。
- 唯一允许的恢复转换：`CANCELLED -> WAITING_FOR_REPAIR`。
- 取消可通过待修复卡片底部“取消”或拖入“已取消”入口完成。
- 取消立即执行、不弹确认；Toast 提供即时“撤销”。
- “已取消缺陷”抽屉长期提供“恢复到待修复”。
- 恢复后原始资料可继续编辑，但不自动开始修复。
- 取消和恢复作为生命周期节点进入 Bug 进展时间线。
- 删除修复中、待更新取消、停止后取消和 Batch 内单 Bug 取消。

## 删除 Bug Cleanup

由于取消只发生在 Repair 前，取消不会存在 Repair Workspace、候选提交或 Update Batch：

- 删除 `BUG_CANCELLED` Cleanup reason。
- 删除取消后创建 Cleanup Execution、Interaction、失败重试和 Bug 详情“取消与清理”。
- Cleanup 只保留提测单关闭后的资源清理职责。
- 不迁移旧 Bug Cleanup 数据。

## 归档与移出归档

- 只有 `DONE` Bug 可以归档。
- 归档不是 Stage；数据使用 `archivedAt`、`archivedByUserId`或等价独立属性。
- 归档可通过已完成卡片底部“归档”或拖入“归档”入口完成。
- 归档立即执行、不弹确认；Toast 提供即时“撤销”。
- 归档抽屉长期提供“移出归档”。
- 移出归档后 Bug 仍是 `DONE` 并回到已完成列。
- 归档/移出归档只记录 Audit，不进入主生命周期时间线。
- 归档 Bug 需要重新打开时，先移出归档，再在已完成详情中提交反馈。

## 唯一合法拖拽矩阵

| 来源   | 目标   | Action                 | 可撤销 |
| ------ | ------ | ---------------------- | ------ |
| 待修复 | 修复中 | 冻结报告并开始自动修复 | 否     |
| 待修复 | 已取消 | 取消 Bug               | 是     |
| 待验证 | 已完成 | 无备注验证通过         | 否     |
| 已完成 | 归档   | 隐藏已完成 Bug         | 是     |

除此之外任何列间或收纳入口拖拽均无效，且目标不高亮。

## 生命周期权限

以下拖拽、卡片按钮、抽屉恢复和详情动作全部只允许 `submission.tester_user_id`：

- 开始修复
- 取消与恢复
- 验证通过
- 验证失败返修
- 归档与移出归档
- 重新打开

工程负责人和其他成员可以查看有权限的信息，但卡片不可拖拽、目标不响应、按钮不可见；服务端 Action 同样必须拒绝越权调用。

## 验收标准

- 待修复卡片底部只展示“取消 / 开始修复”，两个按钮不触发卡片详情点击。
- 待验证卡片底部展示“验证通过”；需要说明或失败时进入详情。
- 已完成卡片底部展示“归档”。
- 取消、归档的拖拽和按钮产生相同结果、Toast 与 Audit。
- 验证通过、开始修复不提供 Toast 撤销。
- 已取消和归档抽屉均可查看只读详情并执行各自恢复操作。
- 看板主列不显示 CANCELLED 或 archived DONE。
- 非测试负责人无法通过 UI 或直接 Action 改变生命周期。
- 旧垃圾桶拖拽状态、不可恢复取消、Bug Cleanup 和多阶段 CANCEL Action 被删除。

## 验证

- Lifecycle Service 测试覆盖取消、撤销/恢复、归档、移出归档和非法阶段。
- 权限测试覆盖测试负责人、工程负责人、项目 Owner 和普通成员。
- Drag transition 单测断言只有四条合法边。
- 浏览器验证拖拽目标、按钮、Toast 撤销、两个抽屉、角色差异和桌面可达性。
